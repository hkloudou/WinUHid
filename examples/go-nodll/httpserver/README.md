# HTTP 参考程序：用网址操作虚拟键盘鼠标

`winuhid-http.exe` 启动时创建虚拟键盘和鼠标，运行期间用网址驱动它们，退出时移除。
基于同目录上一级的 `vhid` 包，不需要任何 DLL，目标机器只要装了驱动。

**没有任何鉴权。** 能访问到这个地址的人就能在这台机器上打字和点击。这只是可行性验证用的参考，正式使用前必须自己加鉴权。

## 运行

前提：已经用测试包的 `install.cmd` 装好驱动。用管理员身份打开命令行：

```
winuhid-http.exe                         监听 127.0.0.1:8765
winuhid-http.exe -addr 0.0.0.0:8765      允许其他机器访问
winuhid-http.exe -log C:\path\http.log   同时把日志写到文件（没有窗口时用）
```

然后在浏览器地址栏或用 curl 访问，例如 `http://127.0.0.1:8765/mouse/move/800/450`。
访问 `http://127.0.0.1:8765/` 可以看到全部接口。

也可以以 SYSTEM 身份运行（服务、计划任务）。这时程序不在用户的桌面会话里，
它会临时在桌面会话里启动自己的一个副本去读屏幕分辨率和指针位置，不需要你传。

## 接口

| 路径 | 作用 |
| --- | --- |
| `/mouse/move/x/y` | 指针放到主屏幕的像素 (x, y) |
| `/mouse/click/x/y` | 移到 (x, y) 左键单击 |
| `/mouse/dblclick/x/y` | 移到 (x, y) 左键双击 |
| `/mouse/rclick/x/y` | 移到 (x, y) 右键单击 |
| `/mouse/down/x/y`、`/mouse/up/x/y` | 在 (x, y) 按下、松开左键，拖拽用 |
| `/mouse/scroll/n` | 滚轮 n 格，正数向上、负数向下 |
| `/mouse/rel/dx/dy` | 相对当前位置移动，给游戏用 |
| `/key/tap/键名` | 按一下键，支持 `ctrl+c`、`win+r` 这种组合 |
| `/key/down/键名`、`/key/up/键名` | 按住、松开 |
| `/type/文字` | 打一串字，按美式键盘布局，一次最多 256 个字符 |
| `/status` | 当前状态：身份、会话、屏幕分辨率、指针位置 |
| `/quit` | 移除设备并退出 |

键名：`a`-`z`、`0`-`9`、`enter`、`esc`、`tab`、`space`、`backspace`、`delete`、`insert`、`home`、`end`、
`pgup`、`pgdn`、`up`、`down`、`left`、`right`、`f1`-`f12`、`ctrl`、`shift`、`alt`、`win`（以及 `lctrl`、`rctrl` 等），
或者直接写编号，如 `0x28`。

## 返回的状态码

每个请求都一定会有答复，不会一直等。

| 状态码 | 含义 |
| --- | --- |
| 200 | 完成。带坐标的接口还确认过指针确实到了那个位置 |
| 400 | 网址写得不对：坐标不是数字、键名不认识、文字太长 |
| 403 | 输入发出去了但没生效：指针没到指定位置。不判断原因（没接显示器、屏幕被远程桌面接管、锁屏……），这个请求后面的点击不再执行 |
| 500 | 驱动报错或超时、读不到屏幕、或者上一个请求还没结束 |

时限：和驱动的每次交互最多等 2 秒；指针到位最多等 0.4 秒；排队等上一个请求最多 3 秒。
"把指针放到 (x, y)"只发一次，之后只是读位置做确认，不会反复重发。

## 启动和退出

- **启动**：创建键盘、相对鼠标、绝对定位鼠标三个虚拟设备，等约 1.5 秒让系统准备好，再开始接受请求。
- **重复启动**：虚拟设备跟着进程走，所以只有"另一个实例还在运行"才会重复。新实例发现地址被占用时，会让旧实例退出、等它移除设备，再创建自己的。
- **退出**：`/quit`、Ctrl+C、关窗口都会先移除设备再退出。进程被强杀时，系统也会自动收回设备。

## 已知的限制

- 带坐标的接口对应的是主屏幕；多显示器时的行为没有测过。
- 相对移动、滚轮、按键、打字只确认驱动接受了，不确认效果（没有通用的办法读回）。
- 以管理员身份（不是 SYSTEM）在远程桌面会话里运行时，读不到本机屏幕，带坐标的接口会返回 500。
